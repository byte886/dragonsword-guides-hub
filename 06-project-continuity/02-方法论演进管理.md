# 方法论演进管理

> 文档定位：当调研方法、操作流程发生变化或改进时，如何记录、更新和传承，确保方法论不会丢失或混乱。
> 核心问题：项目过程中会发现更好的方法，怎么让后续的AI知道用新方法而不是旧方法？

---

## 一、为什么需要方法论管理

### 1.1 常见问题
- 一开始用的方法可能不够好，后来改进了，但旧方法还在文档里
- 不同窗口的AI可能用不同版本的方法，导致结果不一致
- 方法改进的原因和验证结果没有记录，后人不知道为什么改
- 旧方法中有效的部分被一起丢弃了

### 1.2 管理目标
- 每个方法都有明确的版本号和状态（在用/已废弃/实验中）
- 方法变更有记录：改了什么、为什么、效果如何
- 新窗口的AI默认使用最新版本的方法
- 旧方法保留备查，不直接删除

## 三、方法论变更流程

### 3.1 什么时候需要变更方法论
- 发现现有方法有缺陷或遗漏
- 发现更高效/更准确的新方法
- 工具更新导致操作步骤变化
- 项目范围变化，现有方法不适用

### 3.2 变更步骤（5步）

```
发现改进点 → 验证新方法 → 记录变更 → 更新操作手册 → 通知/交接
```

#### 第一步：发现改进点
记录：
- 现有方法的问题是什么
- 改进思路是什么
- 预期效果是什么

#### 第二步：验证新方法
- 在小范围测试新方法
- 对比新旧方法的结果（效率、准确性、覆盖度）
- 确认新方法确实更好

#### 第三步：记录变更
在本文档的"方法论变更日志"中添加一条记录：
- 方法名称和版本号（如 选词法 v1.0 → v1.1）
- 变更内容（具体改了什么）
- 变更原因（为什么改）
- 验证结果（新方法效果如何）
- 变更时间

#### 第四步：更新操作手册
- 更新对应操作手册中的步骤
- 在文档顶部标注版本号和最后更新时间
- 如果是重大变更，保留旧版本的关键内容作为参考

#### 第五步：通知/交接
- 在 05-AI上下文交接指南.md 中更新"当前方法论版本"
- 确保后续窗口的AI使用最新方法

### 3.3 版本号规则
- **v1.0 → v1.1**：小改进，步骤微调，不改变整体流程
- **v1.0 → v2.0**：重大变更，流程重构或方法替换
- **v1.0-beta**：实验中的方法，尚未验证

## 四、方法论变更日志

> 按时间倒序，最新变更在最上面。目前项目还处于v1.0阶段，以下为模板和示例。

### [模板] 方法名 vX.X → vY.Y
- **时间**：YYYY-MM-DD
- **变更内容**：
  - 改了什么1
  - 改了什么2
- **变更原因**：为什么需要改
- **验证结果**：新方法效果如何（数据支撑）
- **影响范围**：哪些文档/产出需要同步更新
- **操作人**：谁做的变更

---

### 示例：选词法 v1.0 → v1.1（示例，非真实变更）
- **时间**：2026-08-XX
- **变更内容**：
  - Google Trends对标词从"GPTs"改为更精准的对标词

- **变更原因**：GPTs作为对标词波动太大，SteamDB的玩家数数据更稳定
- **验证结果**：用新方法验证了3个游戏，结果与实际更吻合
- **影响范围**：01-关卡1-选词操作指南.md
- **操作人**：XXX

## 五、各方法论的已知问题和改进方向

> 记录当前方法的已知不足，为未来改进提供方向。

### 5.1 游戏选词法 v1.0
**已知问题**：
- SimilarWeb的KD数据对新游戏可能不准确（搜索量太少）
- Google Trends对极新游戏可能没有数据
- 竞品层级判断偏主观

**改进方向**：
- 增加SteamDB的玩家数和趋势作为辅助验证
- 增加Google搜索结果数量作为竞争度参考
- 建立更量化的竞品层级判断标准

### 5.2 关键词挖掘法 v1.0
**已知问题**：
- 三大来源（Google下拉、Trends、SimilarWeb）可能覆盖不全
- 同义词合并依赖人工判断，可能有遗漏
- MECE分类没有绝对标准，不同人分类可能不同

**改进方向**：
- 增加Ahrefs、SEMrush等工具作为补充来源
- 建立同义词词典，减少人工判断
- 制定更明确的分类规则

### 5.3 素材搜集法 v1.0
**已知问题**：
- 五维来源检索耗时较长（每个页面30-60分钟）
- 小语种站依赖机器翻译，可能有理解偏差
- 交叉核验的标准不够量化

**改进方向**：
- 建立常用信息源清单，减少检索时间
- 对小语种内容进行二次验证
- 制定更明确的核验等级标准

### 5.4 信息源核验法 v1.0
**已知问题**：
- 很多攻略站内容本身是AI生成的，难以判断原始来源
- 社区信息质量参差不齐
- 时效性判断依赖人工

**改进方向**：
- 建立可信来源白名单和不可信来源黑名单
- 对AI生成内容进行识别标记
- 建立信息时效性自动检查机制
