# AI协作提示词模板与使用规范

> 文档定位：**AI协作规范**。整合队员实战经验和本项目实践，提供可复用的提示词模板和AI协作方法论。
> 来源：大可乐（3群）"立规矩"提示词模板 + 本项目实践总结 + 队员实战经验汇总。
> 核心原则：**给AI立规矩，比要求AI"写好一点"有效10倍**。
> 整理日期：2026-08-27

---

## 一、核心方法论：给AI立规矩

### 1.1 为什么要立规矩

**没有立规矩之前的问题（大可乐踩过的坑）：**
- AI 自己杜撰的游戏玩法
- 武器表里混进了泰拉瑞亚的 Demonite Ore（两个游戏的词条 AI 会串）
- 让它配图，它凭记忆猜图片 URL，路径全错，全部 404
- 页面里出现 AI 提示词、内部说明或测试内容泄漏

**立规矩之后的效果：**
- 111个饰品逐条去官方 wiki 核对来源
- 57个附魔全表带出处
- 图片直链从 File 页面获取并逐张验证返回 200
- 查不到的直接标「官方未收录」
- 新页面 0 事实错误

### 1.2 立规矩的四条原则

| 原则 | 说明 | 反面案例 |
|------|------|---------|
| **小步验证，不问大问题** | 不问"怎么做好网站"，问"根目录有没有 favicon"。问题越小，AI答得越准。 | "帮我做一个好网站" → AI 输出泛泛而谈 |
| **给AI完整上下文** | 直接贴文件路径、报错原文、截图，比"网站报错了"快十倍。 | "网站有问题" → AI 猜半天 |
| **一步一问，接受笨办法** | 别指望一句话让AI干完全部。让它先调研、再给数据、再写页面、再验证，每步你过一眼。 | "帮我从调研到上线全做了" → 中间出错没人发现 |
| **给AI立死规矩** | 任何信息必须有官方出处，找不到就明说，不许编。这条规矩救了整个站的内容质量。 | "写得丰富一点" → AI 开始编造 |

## 二、通用提示词模板

### 2.1 事实调研模板（立规矩版）

**适用场景：** 调研游戏数据、角色属性、武器数值、机制说明等事实性内容。

```
调研 [主题] 的准确数据。

信息源必须实际访问官方 wiki 页面核实，不要凭记忆写。
每条数据注明来源 URL。
查不到的信息明确标注「官方未收录」，禁止编造。

图片直链必须从 File 页面获取，禁止猜测路径，逐个验证返回 200 后只报告通过的。

输出格式：
1. 数据列表（每条带来源URL）
2. 官方未收录的信息列表
3. 有争议/需要交叉验证的信息
```

**使用说明：**
- 200 = HTTP 成功码，表示图片链接有效
- 官方 wiki 没有的数据（如坐骑速度、Boss 价格），宁可标"官方未收录"，也不编一个好看的数字上去
- 这个模板来自大可乐实战，验证后实现"新页面0事实错误"

### 2.2 内容创作模板

**适用场景：** 基于调研素材撰写攻略页面内容。

```
基于以下素材撰写 [页面主题] 的攻略内容。

要求：
1. 只使用提供的素材中的事实，禁止编造素材中没有的信息
2. 素材中冲突的信息，标注「有争议」并列出不同来源的说法
3. 素材中缺失的信息，标注「待补充」，不要自行填补
4. 内容结构：用户意图 → 核心答案 → 详细说明 → 注意事项 → 相关内容
5. 单页目标 600-800 英文单词（不设硬指标，作为信息密度参考）
6. 不是所有页面都适合加表格/数据/步骤，不为凑字数强行添加

素材：
[粘贴调研素材]
```

### 2.3 代码开发模板

**适用场景：** 开发/修改网站代码。

```
基于以下需求开发/修改 [功能描述]。

要求：
1. 纯静态 HTML/CSS/JS，无构建步骤，无框架
2. GA 跟踪代码统一在 js/analytics.js 维护，不要在 HTML 中内联 GA 代码
3. canonical URL 统一为 https://ds-guides.wiki/[语言目录]/[页面名].html
4. 多语言用子目录：/en/、/zh/、/ko/、/ru/、/ja/
5. 修改前先确认 git 状态，避免覆盖已有工作
6. 代码中不要出现中文注释（用英文）
7. 常用代码不需要太多注释，保持简洁

需求描述：
[具体需求]

当前代码：
[粘贴相关代码或文件路径]
```

### 2.4 数据复盘模板

**适用场景：** 分析 GA/GSC 数据，生成复盘报告。

```
分析以下 GA/GSC 数据，生成数据复盘报告。

分析框架：
1. 核心指标概览（曝光、点击、CTR、平均排名、用户数、停留时间）
2. 流量来源分析（自然搜索、直接、引荐、社交）
3. 关键词分析（高曝光低CTR词、高CTR词、新出现的词）
4. 页面分析（高流量页面、低流量页面、跳出率高的页面）
5. 用户行为分析（着陆页、退出页、转化路径）
6. 问题诊断（数据异常、收录问题、技术问题）
7. 行动建议（短期可执行、中期优化、长期规划）

要求：
- 所有结论必须有数据支撑，禁止凭空猜测
- 行动建议要具体可执行，不要泛泛而谈
- 标注数据来源和时间范围

数据：
[粘贴 GA/GSC 数据或文件路径]
```

### 2.5 独立AI检查模板（质量门）

**适用场景：** 网站初版完成后，用另一个AI独立检查，而不是让建站AI自我评价。

```
你是一个独立的网站质量检查员。请检查以下网站/页面，不要参考建站AI的自我评价。

检查清单（4项硬指标）：
1. 页面是不是只有一堆 H2 和摘要，没有把问题讲清楚？（信息密度检查）
2. 有没有 AI 提示词、内部说明或测试内容泄漏到公开页面？（内容纯净度检查）
3. 有没有提供正确的官方入口（Steam 链接、游戏官网等）？（功能完整性检查）
4. 网站有没有明显缺陷，页面是否真正解决搜索需求？（用户价值检查）

额外检查：
- 事实性内容是否有来源标注？
- 不同语言页面是否在讲同一主题？
- 图片链接是否有效（返回200）？
- 站内链接是否有效？

输出格式：
- P0（阻塞上线）：[问题列表]
- P1（严重）：[问题列表]
- P2（建议优化）：[问题列表]
- 通过项：[已通过的检查项]

网站/页面：
[粘贴代码或提供URL]
```

**使用说明：**
- 这个模板来自匿名队员（5站）的实战经验：AI执行+另一个AI挑错，发现的真实问题再反过来更新SOP
- 独立AI发现问题后，自动修改并再次检查
- 通常没有 P0、P1 问题，这一轮才结束
- 如果同一个问题连续两轮都修不好，不要让AI把问题等级降低后强行上线，而是缩小对应页面或功能范围

## 三、场景化提示词

### 3.1 选词场景

```
帮我分析这个游戏词是否适合做热词站。

游戏名：[游戏名]
要求：
1. 先在 SteamDB 查看趋势图（选max），判断是不是新游戏（最近几天开始有players才是新游戏）
2. 在 Google Trends 对比 GPTs，判断热度趋势
3. 在 SimilarWeb 查 KD 和细分关键词数量（KD<30，长尾词>50）
4. 手动在 Google 搜索首页，判断实际竞争强度（前10是什么站，新站有没有位置）
5. 最终判断：做/不做/考虑

注意：工具数据可能骗人，必须手动SERP验证。游戏名主词都是大站的，机会在"游戏名+细分长尾词"。
```

### 3.2 素材采集场景

```
帮我采集 [页面主题] 的素材。

要求：
1. 五维来源检索：英文权威攻略站、中文攻略站、小语种攻略站、Wiki站点、社区/视频
2. 必须提取完整正文保存到本地，禁止只让AI总结摘要（摘要式输入必然导致摘要式输出）
3. YouTube 视频字幕用 TranscriptGenerator 插件提取，自动字幕错漏多，必须和官方wiki交叉核对
4. 每个来源记录：URL、来源类型、核心内容、可信度
5. 交叉核验：重要信息必须2个以上独立来源验证
6. 查不到的信息标注「官方未收录」，禁止编造

输出：素材清单 + 完整正文文件
```

### 3.3 翻译场景

```
帮我把以下英文内容翻译成 [目标语言]。

要求：
1. 游戏术语保持一致，参考已有的翻译规范
2. 专有名词（角色名、技能名、物品名）保持英文或按官方翻译
3. 不要直译，要符合目标语言玩家的表达习惯
4. 翻译后检查：有没有混进其他语言？句子是否自然？
5. 不同语言页面要在讲同一主题，不要漏译或多译

内容：
[粘贴英文内容]
```

## 四、本项目AI协作规范

### 4.1 必须遵守的规矩

1. **真实性原则**：所有事实性内容必须来自真实来源，严禁AI凭空编造
2. **来源标注**：每个信息点都要记录来源链接
3. **交叉核验**：重要信息必须2个以上独立来源验证
4. **查不到就明说**：找不到来源的信息标注「官方未收录」，不要编
5. **修改前确认**：修改代码或内容前先确认 git 状态，避免覆盖用户工作
6. **每轮只改一类**：网站迭代遵循七轮迭代法，每次发布只改一类内容
7. **TDH红线**：页面拿到Google排名后，禁止修改Title、Description、H1

### 4.2 禁止的行为

- ❌ 凭记忆写事实性内容（必须实际访问来源核实）
- ❌ 编造数据、数值、属性
- ❌ 猜测图片URL（必须从File页面获取并验证返回200）
- ❌ 只做摘要式采集（必须提取完整正文）
- ❌ 频繁修改已有排名的页面（要补充内容就新增内页）
- ❌ 把内容、首页、埋点、语言和广告塞进同一次发布

### 4.3 遇到问题时

1. 先读错误信息，定位根因而非绕过
2. 先搜索再动手：Google搜索官方文档/Stack Overflow/GitHub Issues
3. 查项目知识库：`.agents/skills/` 和 `06-project-continuity/` 是否已有相关经验
4. 验证后再执行：找到方案后先确认逻辑正确，再操作
5. 记录经验：解决新问题后更新对应skill或文档

## 五、提示词使用技巧

### 5.1 怎么写好提示词

| 技巧 | 说明 | 示例 |
|------|------|------|
| **角色设定** | 给AI一个明确的角色 | "你是一个游戏攻略网站的内容编辑" |
| **任务明确** | 具体描述要做什么，不要泛泛 | "调研Kalien的技能数据" 而非 "帮我做点内容" |
| **约束清晰** | 列出必须遵守的规则 | "信息必须来自官方wiki，查不到就标未收录" |
| **输出格式** | 指定输出的结构和格式 | "输出：数据列表+来源URL+未收录列表" |
| **示例引导** | 给一个期望输出的示例 | "参考这个格式：[示例]" |

### 5.2 常见错误

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| "写得丰富一点" | AI开始编造内容 | "基于提供的素材撰写，素材中没有的标注待补充" |
| "帮我全做了" | 中间出错没人发现 | 分步骤：调研→数据→页面→验证，每步确认 |
| "网站有问题" | AI猜半天 | 贴具体报错信息、文件路径、截图 |
| "参考一下别人怎么做的" | AI可能直接抄袭 | "分析同行页面的结构和内容方向，独立撰写，不要照抄" |
