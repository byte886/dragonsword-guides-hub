# 项目工作流总览与文档索引

> 文档定位：**统一入口**。描述从0到1搭建游戏热词站的完整工作流，以及每个阶段对应的文档。新AI会话或新人接手时，从本文档开始，3分钟即可了解全貌并找到需要的文档。
> 最后更新：2026-08-27
> 项目：AI出海游戏热词站 - DragonSword: Awakening

---

## 一、完整工作流（7个阶段）

```
阶段1：选词 → 阶段2：关键词挖掘 → 阶段3：素材搜集 → 阶段4：建站开发
                                                          ↓
阶段7：数据复盘 ← 阶段6：上线后SEO ← 阶段5：部署上线
```

每个阶段都有对应的操作手册、方法论和参考文档。下面详细说明。

## 二、各阶段工作流与对应文档

### 阶段1：选词（选什么游戏）

**目标：** 找到有搜索需求、竞争度低、适合新站的游戏热词。

**核心步骤：**
1. SteamDB 找新品/增量热游（看趋势图max，判断是不是新游戏）
2. Google Trends 热度真伪验证（对比GPTs，看趋势线型）
3. SimilarWeb 双维度校验（KD<30，长尾词>50）
4. 谷歌首页人工竞争终判（**选词铁律：工具数据必须手动SERP验证**）
5. 域名规划（先验证后买，.wiki优选，.cc/.xyz避雷）

**对应文档：**
| 文档 | 用途 |
|------|------|
| `01-关卡1-选词操作指南.md` | 5步选词法完整操作手册（含手动SERP验证铁律） |
| `02-关卡2-关键词操作指南.md` | 关键词挖掘+清洗+分类+页面矩阵 |
| `../02-research-data/` | 本项目实际选词调研产出（关键词、竞品分析） |

**关键方法论：**
- 游戏名主词都是大站的，新站唯一机会在"游戏名+细分长尾词"
- 工具数据可能骗人，必须手动打开Google搜索首页验证
- Wikipedia/Fandom/IGN/Steam见到就撤，Reddit/小博客才是机会

---

### 阶段2：关键词挖掘与页面矩阵规划

**目标：** 围绕选定游戏，挖掘足够的长尾关键词，规划页面矩阵。

**核心步骤：**
1. 数据采集（Google下拉词、Trends相关词、SimilarWeb细分词）
2. 意图聚类（同义/近义的词合并，同一个意图做一个页面）
3. 页面矩阵规划（首页+内页，第一批做什么，第二批做什么）
4. 停止条件（最终调研结果必须能支撑至少5个页面，否则不做）

**对应文档：**
| 文档 | 用途 |
|------|------|
| `02-关卡2-关键词操作指南.md` | 关键词挖掘+清洗+分类+页面矩阵完整手册 |
| `../02-research-data/keywords.json` | 本项目关键词结构化数据 |
| `../02-research-data/keywords-cleaning.md` | 关键词清洗过程和最终清单 |

**关键方法论：**
- 一个意图一个页面，每个页面具体解决一个问题
- 不为了凑页面数把同一个意思的关键词硬拆成多个页面
- 停止条件：至少能支撑5个页面才继续建站

---

### 阶段3：素材搜集

**目标：** 为每个页面搜集真实、可验证的素材，确保内容质量。

**核心步骤：**
1. 确定页面关键词（**搜索意图匹配游戏阶段**）
2. 五维来源检索（英文攻略站/中文攻略站/小语种攻略站/Wiki/社区视频）
3. **必须提取完整正文**，禁止只做摘要（摘要式输入必然导致摘要式输出）
4. 交叉核验（重要信息2个以上独立来源验证）
5. 结构化整理（统一格式模板）
6. 质量检查（4项硬指标）

**对应文档：**
| 文档 | 用途 |
|------|------|
| `03-关卡3-素材搜集指南.md` | 五维来源检索+交叉核验+搜索意图匹配完整手册 |
| `04-信息源使用手册.md` | 有哪些信息源、怎么用、怎么核验 |
| `../03-content-materials/` | 本项目实际素材库（27个页面素材+汇总表） |
| `13-AI协作提示词模板.md` | 素材调研提示词模板（立规矩版） |

**关键方法论：**
- 做内容站不是做你认为用户需要的内容，是做用户真正在搜的内容
- 搜索意图必须匹配游戏阶段（新游头两周做故障修复/购买决策，不是深度攻略）
- YouTube字幕是宝藏（官方wiki不写的实战经验），但自动字幕错漏多，必须交叉核对
- 采集同行页面时必须提取完整正文，禁止只让AI总结摘要

---

### 阶段4：建站开发

**目标：** 基于素材，开发纯静态HTML多语言攻略站。

**核心步骤：**
1. 网站模板设计（参考对标网站结构，配色从游戏截图提取）
2. 页面开发（首页+内页，基于页面矩阵和素材）
3. 多语言翻译（英/中/韩/俄/日）
4. SEO基础（canonical、hreflang、sitemap、robots.txt）
5. GA跟踪代码接入（统一在js/analytics.js维护）
6. **独立AI质量检查**（4项硬指标，不是建站AI自我评价）
7. 本地预览验证

**对应文档：**
| 文档 | 用途 |
|------|------|
| `../06-project-continuity/06-PRD产品说明文档.md` | 产品需求文档 |
| `../06-project-continuity/07-开发要求文档.md` | 开发规范和要求 |
| `../06-project-continuity/08-审核报告.md` | 第一次审核报告 |
| `../06-project-continuity/09-最终审核报告.md` | 最终审核报告 |
| `../06-project-continuity/10-content-relationship-map.md` | 内容关联关系图 |
| `13-AI协作提示词模板.md` | 代码开发+独立检查提示词模板 |
| `../04-website/` | 网站代码（Git子模块） |

**关键方法论：**
- 纯静态HTML/CSS/JS，无构建步骤，无框架
- GA代码统一维护，不要在HTML中内联
- 第一版不要上线太多页面（10个左右），质量差会影响排名
- 独立AI检查：AI执行+另一个AI挑错，发现的真实问题更新SOP
- 提取正文仅用于内部研究，发布时仍需需求提炼→结构重组→事实核对→独立撰写→相似度检查

### 阶段5：部署上线

**目标：** 将网站部署到Vercel，配置域名DNS，接入GA/GSC。

**核心步骤：**
1. GitHub推送代码
2. Vercel导入项目，自动部署
3. 域名购买（Spaceship）
4. DNS配置（Cloudflare，DNS only灰色云）
5. 域名验证（Vercel + Cloudflare Domain Connect）
6. GA4接入（创建数据流，添加js/analytics.js）
7. GSC接入（添加资源，提交sitemap，请求索引）
8. 上线验证（电脑+手机访问，GA实时数据，GSC抓取状态）

**对应文档：**
| 文档 | 用途 |
|------|------|
| `06-deployment-guide.md` | Vercel+Cloudflare+Spaceship部署操作手册 |
| `07-ga-gsc-guide.md` | GA/GSC接入与指标查看指南 |
| `08-ga-gsc-practice-handbook.md` | GA/GSC实践手册（看过/没看过的功能页面） |
| `../.agents/skills/playwright-extension/` | 连接用户Chrome进行后台操作 |

**关键方法论：**
- 每个站必须建独立的GA数据流，不能复用ID
- Vercel改环境变量后必须重新部署，不能勾Use existing Build Cache
- Cloudflare代理状态用DNS only（灰色云），不开启Proxied
- favicon显示需要等1-4周，新站更慢，不要急

---

### 阶段6：上线后SEO优化

**目标：** 提升网站在Google的排名和流量，持续迭代优化。

**核心步骤：**
1. 提交sitemap到GSC，主动请求首页索引
2. 检查robots.txt没有误屏蔽
3. **七轮迭代法**（每轮只改一类，用数据验证）：
   - 第一轮：质量基线（结构、语言、来源）
   - 第二轮：网址信号（canonical、www/非www、.html/非.html统一）
   - 第三轮：玩家任务（一页只把一件事讲完）
   - 第四轮：首页入口（首屏改成任务入口）
   - 第五轮：打开速度（PageSpeed优化）
   - 第六轮：测量校准（内部流量过滤、增强衡量、机器人过滤）
   - 第七轮：一次只改一类（写成规矩）
4. GSC数据分析（高展示低CTR词优化，TDH红线）
5. 内链建设（从高流量页面添加指向新页面的内链）
6. 内容补页（GSC查询列表就是选题指南）

**对应文档：**
| 文档 | 用途 |
|------|------|
| `10-post-launch-seo-playbook.md` | 上线后SEO操作手册 |
| `12-网站迭代方法论.md` | 七轮迭代法完整方法论 |
| `08-ga-gsc-practice-handbook.md` | GA/GSC实践手册 |
| `11-队员实战经验汇总.md` | 队员实战经验、踩坑教训 |
| `../06-project-continuity/11-项目任务清单.md` | 当前任务清单和优先级 |

**关键方法论：**
- TDH红线：页面拿到Google排名后，禁止修改Title、Description、H1
- 已上线页面不频繁修改，要补充内容就新增内页
- 每轮只解决一类问题，迭代卡写五句话
- GSC的查询列表就是选题指南，高展示低CTR词需要优化
- 外链对游戏新站效果慢（生命周期短），优先做内容和内链

---

### 阶段7：数据复盘

**目标：** 定期分析GA/GSC数据，评估网站表现，指导后续优化方向。

**核心步骤：**
1. 每周GSC快查（曝光、点击、CTR、排名变化）
2. 每两周GA+GSC完整复盘
3. 每月加SimilarWeb竞品分析
4. 分析框架：
   - 核心指标概览
   - 流量来源分析
   - 关键词分析（高曝光低CTR、高CTR、新词）
   - 页面分析（高流量、低流量、高跳出率）
   - 用户行为分析
   - 问题诊断
   - 行动建议
5. 生成复盘报告，按日期归档
6. 根据复盘结果更新任务清单和优化计划

**对应文档：**
| 文档 | 用途 |
|------|------|
| `../.agents/skills/data-review/SKILL.md` | 数据复盘方法论Skill |
| `../08-data-reviews/` | 数据复盘报告（按日期归档） |
| `08-ga-gsc-practice-handbook.md` | GA/GSC实践手册 |
| `13-AI协作提示词模板.md` | 数据复盘提示词模板 |

**关键方法论：**
- GSC体现"用户在谷歌搜什么看到你"，GA告诉你"用户来了之后干了什么"，两者互补
- 新站前48小时没出词：大概率内容质量低、长度不够、TDH没覆盖核心关键词、或筛词没筛好
- CTR一般排名靠后时都不会高，词排名挺高CTR还很低，就要和竞品对比标题和描述
- 不要只看总体平均，要具体到各个页面的数据以及对应的关键词数据
- 数据表现不错的页面，可以适当优化（添加更多内容、丰富图片/视频/图表），但不要大删大改
